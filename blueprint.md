## ১. প্রজেক্ট পরিচিতি ও ভিশন (Project Overview & Vision)
**NetHelper** হলো একটি এন্টারপ্রাইজ-গ্রেড, মাল্টি-টেন্যান্ট আইএসপি (ISP) ম্যানেজমেন্ট এবং ইআরপি (ERP) সিস্টেম। এটি ইন্টারনেট সার্ভিস প্রোভাইডারদের গ্রাহক ব্যবস্থাপনা, নেটওয়ার্ক অটোমেশন, বিলিং, কোর নেটওয়ার্ক ইন্টিগ্রেশন, ইনভেন্টরি, এইচআর এবং এআই-চালিত অ্যানালিটিক্স সম্পূর্ণভাবে অটোমেটেড করতে ডিজাইন করা হয়েছে।

## ২. এআই এজেন্টদের জন্য কঠোর নিয়ম ও আচরণবিধি (Strict AI Agent Code of Conduct)
> **CRITICAL DIRECTIVE FOR ALL AI AGENTS (Goose, Cline, Roo Code, etc.):** > To maintain project integrity and prevent accumulation of technical debt, you MUST strictly adhere to the following operational rules. Failure to do so will result in code rejection.

1. **NO PLACEHOLDERS OR FAKE CODE:** Do NOT write `// TODO: implement later`, `// Core logic goes here`, or use stub/dummy functions. Every function, controller, service, and repository must be **fully implemented with real, production-ready, and production-grade logic**. 
2. **NO HALF-DONE WORK:** Do not output truncated files or stop mid-file due to laziness or formatting limits. If you are reaching your token or context limit, you must explicitly state the exact line you stopped at in the Ledger, but the code files you save to disk must be syntactically valid and fully functional up to that point.
3. **TYPE SAFETY & ROBUSTNESS:** Since we are using **NestJS (TypeScript)**, all interfaces, DTOs, and entities must be strictly typed. No abuse of the `any` type. Comprehensive error handling (Try-Catch blocks) and logging must be implemented from day one.
4. **DOCKER COMPLIANCE:** Every new service, database migration, or external tool configuration (like FreeRADIUS) must be properly mapped inside the `Dockerfile` and `docker-compose.yml`. Never assume a service exists natively on the host machine.
5. **TESTING:** Write corresponding unit tests (`.spec.ts`) for core business logic, especially for the Billing Engine and RADIUS integrations.

## ৩. টেকনোলজি স্ট্যাক, কনটেইনারাইজেশন এবং আর্কিটেকচার (Tech Stack & Architecture)
* **Containerization & Orchestration:** **Docker & Docker Compose** (Multi-container environment)
* **Backend (Core & Plugins):** **Node.js (NestJS)** (Highly modular, Plugin-driven using Dynamic Modules)
* **Frontend (Web Portal):** **Next.js (React) with Tailwind CSS** (Dockerized)
* **Database Architecture (Multi-Tenant):** **PostgreSQL with Schema-per-Tenant approach** & **Redis** for caching/sessions.
* **Mobile App (Staff & Customer):** **Flutter (Dart)**
* **Architecture Pattern:** Modular Monolith transitioning into independent microservices via Docker networks.
